# Native architecture — revision 12

## CPU and timing

The 68000 boots the cartridge, detects PAL/NTSC and publishes coherent controller snapshots each VBlank. The master SH2 executes the 25 Hz simulation, LIFE/track, active objects, animation, collision, inventory and camera selection. It transforms and sorts geometry and presents completed frames. Shared-RAM wait reads are spaced by 24 NOPs to avoid a terminal-read polling-detector sleep in PicoDrive. Both SH2s rasterize: the master owns logical rows 0–99 and the slave owns 100–199, using the v6 cache-through eight-entry command ring.

The runtime is freestanding C++17 with no heap, OS, filesystem, SDL, STL, RTTI or exceptions. A VBlank phase accumulator catches up simulation ticks independently of rendering. The approved animation clock remains 60 Hz with fractional phase units of 1/1500 second: each logic update consumes 60 units and each original key lasts `duration * 25` units. Walk/run root displacement and pose interpolation carry remainder across keys. Pause, inventory, prompts and books stop the world clock.

## World and script state

The bank supplies 292 original 26-word object records, 207 variables and 45 CVars. Found-item metadata stays in its world record; an active slot owns body, flags, position, angles, LIFE, animation and track state until deactivation writes it back. The imported models use at most 379 vertices, so the single-model scratch bound is 384. The actor pool has 24 slots, each with a bone pose and collision bounds. Activation follows floor/life mode/room visibility and original object order. A capacity error stops with a diagnostic rather than overwriting memory.

LIFE operands and track data are big-endian native words. The interpreter checks cursor/branch/variable/object bounds, caps recursion at eight and caps each invocation at 2048 instructions. It preserves the original caller for expressions on targeted opcodes. Unsupported instructions raise an on-screen LIFE/word error. Sound and music playback remain deferred. SPECIAL now emits bounded presentation effects: death evaporation, hit particles and smoke. Three effect slots each hold at most 30 points, with their own presentation RNG; they do not alter LIFE random choices. Music state remains available to scripts.

The original scripts select action animations, offer/take/equip/read/reload/drop/throw items, schedule enemy arrivals, update health/ammunition and drive stair transitions. The console maps B+Up to run and C to inventory. The first loaded-floor boundary is deliberate: attempts to stage the camera target beyond floor 1 show END OF THIS BUILD.

## Rendering and static props

The packed-pixel VDP presents 320×224 in both regions, with a 320×200 logical scene at `(0,12)`. Each bank has a valid native line table and separate damage bounds. Word writes restore palette index zero correctly. The FPS overlay occupies the upper border and counts completed draws against VBlanks.

Original FITD group geometry, Q15 arithmetic, flat primitives, stable depth order, camera projection, near clipping and conditional foreground masks remain in use. Type-2 eye points occupy one native pixel; small type-3 sphere eyes can shrink to one pixel instead of retaining a three-pixel minimum. Back-facing polygons are culled. Material 2 uses a fixed 50% screen-door pattern to show the scenery through glass. Actor translation/mask tests use the actor's own floor and room. A stable world-level painter sort orders multiple models before their own primitive sort. Vertically disjoint bounds use their camera-relative physical order before horizontal distance, keeping the attic hatch below the standing chest/player without broad height buckets.

One 64,000-byte RAM image stores the current background with static props baked in. Changed camera assets reset the bake and per-slot history; same-camera room links retain them and update the room binding. A cache rebuild binds/copies its camera once. All 20 camera backgrounds use raw ROM storage and aligned word copies; legacy RLE row indexes are built during decode. CRAM reload is conditional on actual palette changes and occurs after drawing but before presenting the frame. Animated/movable models leave the bake, and stationary flags still remain dynamic until their pose/bounds hash has stayed unchanged for 25 world ticks. This keeps sustained pushing out of the bake while allowing settled doors and stopped ghosts to return to it. Per-slot object ownership resets cache history when activation recycles a slot; owners and quiet timestamps use 96 bytes total. Static props must still appear in front of farther moving actors: at rebuild, their colored draw also records visible pixel coverage into an uncached 8000-byte bitmap shared by the row-owning SH2s, including black model pixels, screen-door glass and camera-mask clipping. The bitmap reuses contact/face-sort scratch after up to 384 face indices move to a 768-byte local array. Its bits generate a bounded 3072-span cache without a second monochrome draw or framebuffer scan; scanning reads each bitmap byte once and skips uniform runs. Full restores use direct aligned word reads, and baking copies only the static damage rectangle into the original RAM background. Each span is a four-byte `(u16 pixel start, u16 length)` record. Overlapping foreground props copy only their cached pixels; an exhausted span pool falls back to a normal model draw. A separate gameplay geometry scratch array is shared by combat and LIFE bounds calculations. The renderer shares a union between normal geometry scratch and compact contact-group vertices. At physical model contacts it resolves reciprocal depth per pixel in 64×64 tiles. The 8 KiB tile reuses the 6 KiB face-sort workspace and adds only 2 KiB. Search/Push animations activate physically touching prop groups; flat floor patches are excluded; groups are bounded to 768 vertices and fall back to existing painter output if that bound is exceeded. Near clipping and conditional architectural masks remain applied. Masks read the original camera asset rather than composite bake pixels; RLE cameras use a 600-byte row-offset/skip index. Unrelated foreground models retain their normal painter position after the contact repair. All-front contact vertices reuse camera-space X for cached reciprocal depth; near-crossing groups retain X for clipping.

## Asset bank version 2

Header: `A32X`, `u32 version`, `u32 count`, `u32 size`. Directory entries: `u32 offset`, `u32 packed size`, `u32 unpacked size`, `u16 type`, `u16 flags`. Assets are four-byte aligned with big-endian fields. Flag 1 means `(u8 count, u8 palette index)` RLE; the renderer retains support for it, but this revision stores all camera backgrounds raw to remove camera-change decompression.

This bank contains 1847 assets, 3,349,288 bytes: floor 0 (one room/five cameras), floor 1 (eight rooms/fifteen cameras), both 272-model/305-animation banks, 563 LIFE scripts, 45 tracks, object/variable/define state, title/palettes, item text and 21 English book entries. Names identify floor and room/camera. Models keep the original 36-byte header; the primitive offset points to an array of u32 offsets, followed by compact variable-length primitives `(u8 type,count,color,material; u16 size; u16 indices[count])`. The largest supported model has 384 vertices, 40 groups and 384 primitives. Text/book control codes are converted to uppercase printable text and line breaks for the small native font. Copyright (source byte A9) becomes `(C)` and the I-Motion separator (FA) becomes `-`, avoiding unsupported glyphs. Seven type-13 UI assets contain `u16 width, u16 height` followed by raw indexed pixels. The host importer precomposes the original ITD_RESS:4 corners, repeating rails and 44×8 title plaque. The title panel matches their colors to the existing title palette; gameplay panels retain the original indices. Runtime panels use aligned word copies, including black pixels, and merge their rectangle into per-bank damage. They require no additional RAM bitmap, decompressor or palette changes. Panel coordinates and widths are even and within the logical scene. The single-panel console layout and controls remain intact.

`assets/manifest.json` records original input and bank hashes. The importer reads the supplied installation without modifying it. Converted game resources are separate from the engine license and are excluded from the source ZIP.

## Memory and diagnostics

The RELEASE module occupies 84,228 SDRAM bytes; BSS uses 160,568. Static SDRAM ends at `0x0603BC40` (244,800 bytes), leaving 960 bytes below the stack reservation. The master reserves 12 KiB and the slave 4 KiB at the top of 256 KiB SDRAM. The linker rejects static allocations at or above `0x0603C000`. Framebuffer RAM is separate. This is a tight budget; later systems need measured reuse, fewer live poses, or overlays rather than unchecked additions.

COMM registers retain the v6 coherent input, sequence, region and heartbeat protocol. `debug_state[32]` preserves its first sixteen timing/player/render words and adds floor, room, menu, script-fault LIFE/word/code, inventory/in-hand/prompt, actor-pool peak, world ticks, selected action, health, book, finish and camera-target state. PROFILE builds retain SH7604 FRC scopes; RELEASE removes timer instrumentation. See the v6 architecture report for the inherited mailbox details and `PERFORMANCE.md` for the current measurements.
